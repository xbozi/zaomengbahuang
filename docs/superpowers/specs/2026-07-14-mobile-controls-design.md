# 手机端摇杆与按钮操控设计

## 背景与根因

项目现有角色直接读取 Godot InputMap 中的动作，例如 `move_left`、`move_right`、`jump`、`normalhit` 和五个技能动作。当前分支已经尝试新增 `MobileControls`，但最新已导出的 APK 早于触控场景的无 BOM 修复；APK 中的 `MobileControls.tscn` 无法解析，因此进入关卡后完全不显示触控控件。

现实现还使用普通 `Button` 承载战斗动作。它不能作为双手多点触控的可靠基础，即使重新导出后能够显示，也不能保证左手持续移动时右手同时攻击或释放技能。

## 目标

- 安卓横屏关卡自动显示手机触控层。
- 左手使用浮动虚拟摇杆，右手使用动作按钮。
- 支持持续移动时同时普攻、跳跃或释放技能。
- 复用现有 InputMap 和角色逻辑，不重构五个角色的战斗代码。
- 保留 PC 键盘操作；PC 可通过现有设置开关显示触控层以调试布局。
- 触控场景加载失败时不阻塞关卡运行，并输出明确日志。

## 非目标

- 本次不增加自定义键位拖拽、缩放和透明度设置。
- 本次不改造背包、菜单等非战斗界面的触控交互。
- 本次不抽象全项目统一输入服务。
- 本次不制作最终美术按钮贴图；先使用清晰、半透明且可替换的基础样式。

## 方案选择

采用独立的原生多点触控层：左侧脚本按触点 ID 管理摇杆，右侧使用 `TouchScreenButton`。两者向现有 InputMap 注入动作。

不继续修补普通 `Button` 方案，因为它不能可靠满足双指操作；也不重构全项目输入层，因为改动面和回归风险明显超过当前目标。

## 组件设计

### `MobileControls.tscn`

- 根节点使用独立高层 `CanvasLayer`，避免依赖关卡现有 HUD 的层级和尺寸。
- 内部全屏 `Control` 负责响应式布局。
- 左下为浮动摇杆操作区；触点必须从左侧区域开始才归摇杆管理。
- 右下放大号普攻、跳跃按钮。
- 五个技能按钮围绕主按钮呈弧形排列。
- 法宝、无双、阵法使用较小按钮，放在右上边缘并避开现有 HUD。
- 所有战斗按钮使用 `TouchScreenButton`，不用普通 `Button`。

### `MobileControls.gd`

- 记录摇杆拥有的手指索引，其他触点不进入摇杆状态。
- 根据水平轴强度调用 `Input.action_press()`，映射 `move_left` / `move_right`。
- 摇杆上推映射 `Exit`，下推映射 `down`，均带独立死区。
- 手指抬起、触控取消、窗口失焦、节点隐藏或退出场景时释放摇杆动作并复位。
- viewport 尺寸变化时重新计算控件区域和摇杆安全范围。
- 不负责逐个连接右侧按钮；按钮通过场景中的 `action` 属性直接映射 InputMap。

### `BaseThroughLevel.gd`

- 关卡 `_ready()` 中幂等挂载触控场景。
- 安卓端自动挂载；非安卓端仅在调试设置打开时挂载。
- 同一关卡只允许一个移动控制层。
- 资源加载或实例化失败时记录警告并继续关卡逻辑。

### 设置界面

- 保留 `MobileControlsShow` 作为 PC 调试显示开关。
- 安卓端始终自动启用；设置界面显示有效状态，避免按钮写着“关闭中”但控件仍自动显示。
- 设置变更继续沿用 `MainSet.set_data` 和 `MemoryClass.main_bc()` 的现有持久化流程。

## 动作映射

| 控件 | Input action |
|---|---|
| 摇杆左 / 右 | `move_left` / `move_right` |
| 摇杆上 / 下 | `Exit` / `down` |
| 普攻 | `normalhit` |
| 跳跃 | `jump` |
| 技能 1–5 | `slz` / `lys` / `lyfb` / `hmz` / `hytj` |
| 法宝 | `MagicWeapon` |
| 无双 | `无双` |
| 阵法 | `阵法` |

## 输入数据流

`屏幕触摸 → 摇杆或 TouchScreenButton → Godot Input action → BaseHero / 角色脚本`

移动控制层只适配输入设备，不复制技能判定、冷却、角色状态或移动规则。PC 键盘和手机触摸可以驱动同一组 action。

## 布局与适配

- 以项目的 940×590 横屏 viewport 为基准。
- 使用项目现有 `canvas_items + expand` 拉伸策略，并为超宽屏保留边缘安全距离。
- 左右触控区空间分离：左侧只管理摇杆起触，右侧交给 `TouchScreenButton`。
- 控件保持半透明，主按钮大于技能按钮，低频按钮最小。
- 第一版不引入美术资源依赖，节点结构允许后续直接替换纹理。

## 异常处理

- 每个由摇杆按下的 action 都必须由同一组件释放，防止角色卡在移动状态。
- 触控层隐藏、释放或切换关卡前执行统一清理。
- 输入动作不存在时输出明确警告，不静默失效。
- 场景重复挂载时直接返回。
- 触控资源加载失败不影响角色和关卡继续创建。

## 验证策略

1. 更新静态结构检查，要求动作按钮节点类型为 `TouchScreenButton`，并检查全部 action 映射。
2. 新增 Godot 资源测试，真实加载和实例化 `MobileControls.tscn`，避免仅靠字符串检查漏掉 BOM、语法和节点类型错误。
3. 使用合成触摸事件检查摇杆手指索引、方向切换、死区和释放清理。
4. 导出后检查 APK 包含最新的 `MobileControls.tscn`、`MobileControls.gd` 和关卡挂载代码。
5. 安卓模拟器或真机验收：持续向右移动时依次执行普攻、跳跃、技能、法宝、无双和阵法，移动不得中断，也不得出现粘键。

## 验收标准

- 最新 APK 进入任一继承 `BaseLevel` 的关卡后可见触控层。
- 左手持续控制移动时，右手按钮可同时响应。
- 抬起摇杆手指后角色停止水平移动。
- 切换关卡或隐藏触控层后没有残留按下的 action。
- PC 默认不显示触控层，键盘输入行为保持不变。
- Godot 能真实解析并实例化触控场景，APK 内包含修复后的资源。
